## הארכיטקטורה

```
מכשיר                          │  proxy (Cloudflare Worker / Vercel)   │  Anthropic
─────────────────────────────  │  ──────────────────────────────────   │  ─────────
stateSummary()  ──────────────►│  1. rate limit (טוקן אנונימי)          │
(תקציר אנונימי)                 │  2. שכבת סירוב דטרמיניסטית ◄── חוסמת   │
                               │  3. מחזיק את ANTHROPIC_API_KEY  ──────►│  Messages API
                               │  4. ללא לוגים                          │
```

**ה-proxy הוא רזה בכוונה.** תפקידו: להחזיק את המפתח, לחסום מה שאסור, ולא לזכור כלום.

### כללי ה-proxy

- **אפס לוגים של תוכן.** לא בקשות, לא תשובות, לא תקצירי מצב. מטריקות מצרפיות בלבד (ספירות, שגיאות).
- **rate limiting בלי חשבונות.** טוקן אנונימי שנוצר במכשיר, או App Attest / Play Integrity. **לא** מזהה משתמש.
- **`effort: "low"`** — התשובות הן 2–4 משפטים. זה מוריד עלות ולטנציה משמעותית.
- **streaming** לחוויית הצ'אט.

## מה חוצה את הרשת — והחלטה שכבר הוכרעה

היוצא היחיד מהמכשיר הוא הפלט של `stateSummary()`.

**מה שנשאר תמיד במכשיר:** היומן (`LOG`), השם, וכל היסטוריה.

### `PROFILE.meds` — הוכרע: שולחים דגלים, לא טקסט

`stateSummary()` בדמו שולחת את **הטקסט החופשי** שהמשתמש הקליד בשדה התרופות, וגם גיל/משקל/מין. שדה התרופות הוא **השדה הכי מזהה באפליקציה** — הוא יכול להכיל מצב רפואי, ואפילו שם.

**זה מיותר.** `MED_FLAGS` כבר עושה את ההתאמה **מקומית** (`f.kw.some(k => meds.includes(k))`). לכן:

- הוסף שדה `id` לכל רשומה ב-`MED_FLAGS` (`'lithium'`, `'maoi'`, `'ssri'`, `'tramadol'`).
- `stateSummary()` שולחת את **מזהי הדגלים שנדלקו** — `["ssri"]` — ולא את הטקסט.
- היועץ מקבל בדיוק את מה שהוא צריך כדי להזהיר על האינטראקציה. הטקסט הגולמי לעולם לא עוזב את המכשיר.

גיל / משקל / מין: לשיקול — הם רלוונטיים לשונות בין-אישית, והם הרבה פחות מזהים מטקסט חופשי. אם שולחים, לשלוח בטווחים ולא בערכים מדויקים.

## שכבת הסירוב הדטרמיניסטית — חוסמת להגשה לחנות

**הבוחן בחנות יקליד "כמה MDMA לקחת".** ה-`SYSTEM_PROMPT` אוסר את זה, אבל הנחיה למודל אינה ערובה — ודחייה תחת סעיף 1.4.2 היא דחייה שאין ממנה דרך חזרה (ראה [`app-store.md`](app-store.md)).

**לפני שהבקשה מגיעה למודל**, ב-proxy: שאילתות שמבקשות **כמות / מינון / הכנה / השגה** נחסמות בקוד ומחזירות תשובת harm-reduction קבועה.

זה משרת שתי מטרות בבת אחת:
1. זה עומד בחוק הקשיח #1 של המוצר גם כשהמודל טועה.
2. זה הדבר היחיד בשכבת ה-AI שאפשר **להוכיח** בהערות לבוחן.

הסירוב לא מטיף — הוא מסביר מה כן אפשר לשאול (תזמון, חפיפות, בטיחות), בהתאם לטון המוצר.

## ה-SYSTEM_PROMPT

הנוסח בדמו טוב ותואם את ארבעת החוקים הקשיחים. **שמור עליו; אל תרכך.** נקודות שאסור לאבד בשכתוב:

- מידע כללי לצמצום נזקים בלבד — לא ייעוץ רפואי, לא אבחון, לא מרשם.
- **לעולם לא** מינונים, כמויות, לוחות מינון-חוזר, או הוראות שימוש/הכנה.
- **כן** מותר: תזמון, חפיפות, ועקרונות בטיחות (הידרציה, לא לשלב מדכאים, לא לבד, לא לנהוג, ערכות בדיקה).
- לא לעודד שימוש. אם המשתמש כבר צרך — לעזור לו להיות בטוח יותר.
- ההערכות הן ממוצעי PK; שונות בין-אישית גדולה.
- סימן חירום (חוסר תגובה, קוצר נשימה, כאב חזה, חום קיצוני, פרכוסים) → **מד״א 101** מיד, ושכיבה על הצד בדיכוי הכרה.
- מצוקה נפשית → **ער״ן 1201**.
- 2–4 משפטים.

## נפילה חיננית

הדמו כולל `localReply()` — מענה מקומי מבוסס-כללים שרץ כשה-API לא זמין. **שמור אותו.** הוא נותן:

- עבודה במצב offline
- עמידות לתקלת proxy
- מסלול שבו **שום דבר לא עוזב את המכשיר** — שווה לשקול כהעדפה שהמשתמש יכול לבחור

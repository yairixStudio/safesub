# הסטאק — החלטה ונימוק

> חלק מ-[`../CLAUDE.md`](../CLAUDE.md) · עודכן: **2026-08-28**

> ⚠️ **ההחלטה התהפכה ב-2026-08-28: React Native (Expo).** המסמך למטה הוא הנימוק המקורי ל-Capacitor ונשמר כתיעוד. מה שקרה בפועל: הפורט ל-RN בוצע במלואו ב-`app/` — ה-CSS נכתב מחדש כ-StyleSheet, הגרף ב-`react-native-svg`, ה-RTL ידני (`dir.row`), והמנוע/הקטלוג/המילונים עברו 1:1 עם בדיקת golden. עלות הפורט הייתה בדיוק מה שהטבלה למטה חזתה — והיא שולמה.

## ההחלטה

**Vite + Capacitor, מעל הקוד הקיים. לא שכתוב.**

```
Vite (build) → אותו קוד → ┬ Capacitor iOS     (Xcode → App Store)
                          ├ Capacitor Android (Studio → Play)
                          └ dist/ סטטי        (אתר / PWA)
```

הדמו הוא כבר אפליקציה — הוא פשוט רץ בדפדפן. Capacitor אורז אותו ל-WKWebView ב-iOS ול-WebView ב-Android, ונותן גישה native (אחסון, התראות, האפטיקה, safe-area). **גרסת הדפדפן היא אותו build בדיוק** — אפס עבודה נוספת.

**זמנים:** אפליקציה שרצה על אייפון ואנדרואיד — יומיים. מוכן לחנות — 2–3 שבועות, והרוב מזה הוא אחסון מקומי וה-proxy, לא הפורט.

## למה לא React Native / Expo

"קוד אחד לשלוש פלטפורמות" נכון בסלוגן. בפועל RN זורק כמעט הכל:

| מה שקיים ב-`demo-reference.html` | ב-Capacitor | ב-React Native |
|---|---|---|
| ~600 שורות CSS (משתנים, `aspect-ratio`, גרדיאנטים, inset shadows) | as-is | אין CSS — שכתוב מלא ל-StyleSheet |
| `renderChartSvg` — בניית path ידנית | as-is | שכתוב ל-`react-native-svg` |
| swipe pager (`transform` על `.ptrack`) + long-press | as-is | שכתוב ל-Reanimated / Gesture Handler |
| `dir="rtl"` שעובד | as-is | RTL ב-RN הוא כאב ראש נפרד |
| גרסת דפדפן | אותו build | Expo Web מרנדר עיצוב כזה גרוע |
| מנועי PK + אינטראקציות (JS טהור) | as-is | as-is |

השורה האחרונה היא היחידה שעוברת בשני המקרים. Flutter גרוע יותר — Dart, שכתוב של 100%.

**ויש נימוק שני, לא טכני:** Capacitor נותן ערוץ הפצה web מלא שלא תלוי באף חנות. ראה [`app-store.md`](app-store.md) — זה לא תוכנית ב', זה הערוץ שעובד בזמן שממתינים לתשובה מ-Apple.

## פריימוורק — החלטה נפרדת, ואפשר לדחות

הקוד היום vanilla עם `innerHTML`. זה עובד ויעבוד. אם האפליקציה תגדל (הגדרות, היסטוריה, ניהול מצב), **Svelte** הוא המועמד: הכי קרוב ל-DOM רגיל, מאמץ המרה מינימלי, ובלי VDOM שיילחם בגרף ה-SVG.

**אל תערבב את זה עם החלטת הפלטפורמה.** Vite נכנס עכשיו (זול, נדרש ל-Capacitor בכל מקרה). Svelte — רק אם וכאשר.

## אחסון מקומי — הפער הגדול ביותר

`demo-reference.html` מחזיק `let LOG = []` בזיכרון ומשקף אותו ל-`localStorage` (`persist()/restore()/wipeAll()`, מאז 2026-08-28). זה מספיק לדמו בדפדפן — **לא** ל-native, ולכן ההבטחה המרכזית של המוצר עדיין לא ממומשת שם.

הפשט: `store.js` עם שלוש פונקציות — `load()` / `save()` / `wipe()` — ומאחוריהן:

| פלטפורמה | מנגנון |
|---|---|
| iOS / Android | Capacitor Preferences (JSON blob) או `@capacitor-community/sqlite` |
| דפדפן | IndexedDB |

**אל תסתמך על IndexedDB ב-iOS ל-production.** WKWebView מפנה אותו תחת לחץ אחסון — וזה איבוד יומן, כלומר הפרה של ההבטחה המרכזית. ב-native לך על אחסון native.

`wipe()` הוא לא nice-to-have: מחיקה מלאה בהגדרות היא חלק מעמדת הפרטיות ומופיעה בקארד הפרטיות של הדמו.

## החלטה פתוחה: `def:` הממולא מראש

ב-`SUBS` יש ערכי ברירת מחדל למינון (`def:75` ל-MDMA, `def:40` לקטמין, וכו׳).

- **בעד השארה:** "רישום בנגיעה אחת" הוא הבטחת ליבה של המוצר. הסרת ה-`def` מוסיפה חיכוך לכל רישום — וחיכוך ברישום פוגע ישירות במטרה, כי יומן חלקי = גרף שקרי = ייעוץ גרוע.
- **בעד הסרה:** שדה מ״ג עם ערך ממולא מראש הוא הדבר היחיד באפליקציה שנראה כמו המלצת מינון. ראה [`app-store.md`](app-store.md) — סעיף 1.4.2.
